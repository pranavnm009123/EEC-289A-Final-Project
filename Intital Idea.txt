# Model-Free vs Model-Based RL: Complete Educational Guide 

Let me break down exactly what you'll be building and why it matters.

## The Core Problem

**Question**: Should an RL agent learn by trial-and-error in the real environment (model-free), or should it learn a model of how the world works and plan using that model (model-based)?

Think of it like learning to play chess:
- **Model-free**: Play thousands of games, slowly learn "in this position, this move tends to work"
- **Model-based**: Learn the rules of chess (the "model"), then think ahead by simulating moves in your head

## What Each Approach Does

### 1. PPO (Model-Free - Proximal Policy Optimization)

**What it learns**: A direct mapping from states to actions
- Sees: current observation (e.g., "I'm in a room, door is to my right")
- Outputs: action probabilities (60% go right, 30% go forward, 10% turn left)

**How it learns**:
1. Take actions in the environment
2. Get rewards (or not)
3. Update policy to increase probability of actions that led to rewards
4. Repeat millions of times

**Strengths**:
- Simple, stable, well-understood
- Works well when you can collect lots of experience
- No assumptions about world structure

**Weaknesses**:
- **Sample inefficient**: needs tons of environment interactions
- Can't plan ahead - purely reactive
- Relearns everything from scratch for new tasks

### 2. Dyna-Q (Model-Based - Simple World Model)

**What it learns**: 
- A policy (like PPO)
- PLUS a model: "If I'm in state S and take action A, I'll end up in state S' and get reward R"

**How it learns**:
1. Take real actions in environment (like PPO)
2. Learn model: s, a → s', r
3. Use model to generate **imaginary experiences**
4. Train policy on both real AND imaginary experiences

**Example**:
- Real experience: "In room 1, went right, ended up in room 2, got reward 0"
- Model learns: room1 + right → room2
- Imaginary experience: "What if I was in room 3 and went left?" → simulate this without actually doing it

**Strengths**:
- More sample efficient - learns from real + imagined data
- Can do limited planning (simulate a few steps ahead)
- Transfers knowledge: model helps learn related tasks faster

**Weaknesses**:
- Model errors compound (bad predictions → bad policy)
- Still relatively simple planning

### 3. World Model + Planning (Dreamer/MuZero-style)

**What it learns**:
- A **latent world model**: compresses observations into compact representations, predicts future in this compressed space
- Learns: observation → latent state, latent state + action → next latent state + reward

**How it plans**:
1. Encode current observation into latent state
2. Imagine many possible action sequences by simulating in latent space
3. Pick the sequence with best predicted outcome
4. Execute first action, repeat

**Example in MiniGrid**:
- Current state: "See a locked door and key nearby"
- Simulate: "If I pick up key (3 steps), go to door (2 steps), unlock it (1 step) → reach goal (+1 reward)"
- Compare to: "If I go directly to door without key → stuck (0 reward)"
- Choose first plan

**Strengths**:
- **Most sample efficient**: learns from imagined rollouts in compact latent space
- Sophisticated planning - can look many steps ahead
- Learns reusable world knowledge

**Weaknesses**:
- Complex to implement
- Can hallucinate impossible transitions if model is poor
- Computationally expensive (running planning at every step)

## Your Project's Exact Task

### Environments: MiniGrid Navigation Tasks

You'll test on 4 sparse-reward navigation tasks of increasing difficulty:

1. **Empty-8x8**: Navigate to goal in empty room (baseline)
2. **DoorKey-8x8**: Find key, unlock door, reach goal
3. **MultiRoom-N4-S5**: Navigate through multiple connected rooms
4. **KeyCorridor**: Long corridor with locked doors requiring keys

These are chosen because:
- **Sparse rewards**: Only get +1 when reaching goal, 0 otherwise (hard for model-free)
- **Credit assignment**: Actions early (get key) only matter much later (unlock door)
- **Exploration**: Requires discovering key sequences
- **Clear success metric**: Either reach goal or don't

### What You'll Measure

**1. Sample Efficiency**
- X-axis: Number of environment steps
- Y-axis: Success rate (% of episodes reaching goal)
- **Key question**: Which method learns fastest with limited data?

**2. Computational Cost**
- Wall-clock time to reach 80% success rate
- FLOPs per episode
- **Key question**: Is model-based faster in real time despite extra computation?

**3. Generalization**
- Train on 8x8 grid, test on 16x16 grid
- **Key question**: Does world model transfer better than memorized policy?

**4. Failure Mode Analysis**
- Where does each method get stuck?
- Model-free: Random exploration that never finds key?
- Model-based: Bad model predictions leading to suboptimal plans?
